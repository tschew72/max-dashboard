# WI-103: System Metrics Bar

**Type:** Feature  
**Priority:** Medium  
**Estimated Effort:** 1.5–2 hours  
**Dependencies:** None (standalone component)

---

## Description

A compact top bar on the home page showing live CPU, RAM, and DISK usage as mini progress bars. Updates every 10 seconds via polling. Color-coded: green (<60%), yellow (60–80%), red (>80%). Inspired by ClawBridge's system metrics aesthetic.

---

## Technical Context

### Data Sources (Linux)
- **CPU:** Read `/proc/stat` — parse `cpu` line for user/nice/system/idle/iowait values. Calculate percentage from delta between two reads (need 1s sampling interval on first call, then delta from previous).
- **RAM:** Read `/proc/meminfo` — parse `MemTotal`, `MemAvailable` (or `MemFree + Buffers + Cached` as fallback). Percentage = `(Total - Available) / Total * 100`.
- **DISK:** Run `df / --output=pcent` or parse `df -h /` — extract used percentage for root filesystem.

### Existing Infrastructure
- The dashboard already has a `HealthData` type with `memory.percent` and `disk.percent` fields (see home page `page.tsx`)
- Consider whether to extend the existing health endpoint or create a new dedicated metrics endpoint
- Existing `InfraHealthPanel` component already shows some health data — this new bar is a **compact always-visible** version at the top

## Files to Create

### 1. `app/api/system/metrics/route.ts` — Metrics Endpoint
**Purpose:** Returns current CPU, RAM, and DISK usage percentages.

**Implementation:**
```typescript
// GET /api/system/metrics
// Response:
{
  cpu: 45,      // percentage (0-100)
  mem: 67,      // percentage (0-100) 
  disk: 24,     // percentage (0-100)
  timestamp: "2026-03-09T15:00:00Z"
}

// CPU Calculation:
// 1. Read /proc/stat line starting with "cpu " (aggregate all cores)
// 2. Parse: user nice system idle iowait irq softirq steal
// 3. total = sum of all fields; idle_total = idle + iowait
// 4. Store previous reading in module-level variable
// 5. If previous exists: cpu% = 100 * (1 - (idle_delta / total_delta))
// 6. If first read: take two samples 100ms apart within the request
//
// Read /proc/stat format:
//   cpu  12345 678 9012 345678 901 23 45 67 0 0

// RAM Calculation:
// 1. Read /proc/meminfo
// 2. Parse MemTotal and MemAvailable (both in kB)
// 3. mem% = Math.round((1 - MemAvailable / MemTotal) * 100)

// DISK Calculation:
// 1. exec: df / --output=pcent | tail -1
// 2. Parse integer from output (e.g., " 24%")
// 3. Or: read /proc/mounts + statvfs for pure-Node approach

// Error handling:
// - If /proc/stat unavailable (non-Linux): return cpu: -1
// - If any metric fails: return -1 for that metric, others still populated
// - Always return 200 with available data
```

### 2. `components/dashboard/SystemMetricsBar.tsx` — Metrics Bar Component
**Purpose:** Compact inline bar with 3 mini progress indicators.

**Implementation:**
```typescript
// Props: none (self-contained, fetches own data)
// Renders at very top of home page, above all other content

// Layout:
// ┌──────────────────────────────────────────────────────┐
// │  CPU ▓▓▓▓▓▓░░░░ 45%   RAM ▓▓▓▓▓▓▓░░░ 67%   DISK ▓▓░░░░░░░░ 24%  │
// └──────────────────────────────────────────────────────┘

// Each metric:
//   Label (CPU/RAM/DISK) in gray (#8b949e)
//   Mini progress bar: 80px wide, 8px tall, rounded
//   Percentage text: bold, color matches bar

// Color coding:
//   0-59%  → green (#3fb950) — healthy
//   60-79% → yellow (#d29922) — warning
//   80-100% → red (#f85149) — critical

// Behavior:
//   Fetch /api/system/metrics on mount
//   Re-fetch every 10 seconds (setInterval)
//   Smooth transition on value change (CSS transition on width, 0.5s ease)
//   If metric returns -1, show "N/A" in gray

// Styling:
//   Background: transparent or very subtle (#0d1117 matching page)
//   Bar track: #21262d
//   Bar fill: color per threshold above
//   Height: ~32px total (compact)
//   Flexbox: centered, gap-6 between metrics
//   Font: 12px, monospace for numbers

// State:
const [metrics, setMetrics] = useState<{ cpu: number; mem: number; disk: number } | null>(null)

useEffect(() => {
  const fetchMetrics = () => fetch('/api/system/metrics').then(r => r.json()).then(setMetrics).catch(() => {})
  fetchMetrics()
  const interval = setInterval(fetchMetrics, 10000)
  return () => clearInterval(interval)
}, [])
```

## Design Notes

- Keep it minimal — this is a glanceable status bar, not a detailed monitoring panel
- The existing `InfraHealthPanel` shows similar data in a larger format; this bar complements it as an always-visible summary
- Consider: if the existing `/api/health` endpoint already returns memory/disk, extend it with CPU rather than creating a separate endpoint. Check if reuse is cleaner.
- Pure CSS progress bars (no library needed): `div` with background color and `width: ${percent}%`
- On mobile: stack vertically or hide (media query `hidden sm:flex`)
