# WI-101: Emergency Stop

**Type:** Feature  
**Priority:** Critical  
**Estimated Effort:** 2 hours  
**Dependencies:** Existing Agent Flow page (`/flow`), `AgentDetailPanel.tsx`

---

## Description

A kill switch button in the Agent Flow (`/flow`) page's node detail panel that aborts a running agent session. When an agent node is clicked and its status is `running`, a red "⛔ Stop" button appears. Clicking it immediately aborts the agent's active session via the OpenClaw CLI/gateway.

---

## Technical Context

### OpenClaw CLI Discovery
- `openclaw sessions` — lists sessions with `--active <minutes>`, `--agent <id>`, `--all-agents` flags
- `openclaw gateway stop` — stops the entire gateway (NOT what we want)
- **No direct `abort` subcommand exists** in `openclaw sessions`
- **Approach:** Use the OpenClaw Gateway RPC/API. The gateway runs on `localhost:3020` (default). Check for:
  1. `openclaw gateway --help` for RPC endpoints
  2. Direct HTTP call to gateway API: `POST http://localhost:3020/api/sessions/<key>/abort` or equivalent
  3. Fallback: `kill` the process directly — sessions list includes PIDs when `--json` is used
  4. Nuclear fallback: `pkill -f "openclaw.*agent=<agentId>"` — process-level kill

### Existing Flow Page Architecture
- `app/(dashboard)/flow/page.tsx` — main flow page with React Flow canvas
- `components/flow/AgentNode.tsx` — individual agent node component
- `components/flow/AgentDetailPanel.tsx` — slide-out panel when node is clicked
  - Already has `AgentNodeData` type with status, cost, tokens, model info
  - Status colors defined: `idle=#888`, `running=#7c3aed`, `done=#22c55e`, `error=#ef4444`
- `components/flow/types.ts` — shared type definitions
- SSE connection already updates agent statuses in real-time

## Files to Create

### 1. `app/api/agents/[agentId]/stop/route.ts` — POST Endpoint
**Purpose:** Aborts the running session for a given agent.

**Implementation:**
```typescript
// POST /api/agents/:agentId/stop
// Body: { sessionKey?: string } (optional — if omitted, find active session)

// Steps:
// 1. Validate agentId exists (check /root/.openclaw/agents/<agentId>/ exists)
// 2. Find active session:
//    a. Run: openclaw sessions --agent <agentId> --active 5 --json
//    b. Parse JSON output to get active session key/PID
// 3. Attempt abort via gateway API:
//    a. Try POST http://localhost:3020/api/v1/sessions/<sessionKey>/abort
//    b. If no gateway API: try process kill via PID from sessions list
//    c. Fallback: exec(`kill -SIGTERM <pid>`) then after 3s `kill -SIGKILL <pid>`
// 4. Return { success: true, agentId, sessionKey, method: "gateway"|"process" }
// 5. On error: return { success: false, error: "..." } with 500

// Security: Validate agentId is alphanumeric (prevent path traversal)
// Timeout: 10s max for the entire operation
```

### 2. `components/flow/AgentDetailPanel.tsx` — Add Stop Button
**Changes:**

// In the detail panel component, after the status display section:

// Add state:
const [stopping, setStopping] = useState(false)
const [stopError, setStopError] = useState<string | null>(null)

// Add handler:
async function handleStop() {
  if (!confirm(`⛔ Stop agent "${agent.label}"? This will abort the current session.`)) return
  setStopping(true)
  setStopError(null)
  try {
    const res = await fetch(`/api/agents/${agent.id}/stop`, { method: 'POST' })
    const data = await res.json()
    if (!data.success) throw new Error(data.error || 'Stop failed')
    // SSE will pick up the status change automatically
  } catch (err: any) {
    setStopError(err.message)
  } finally {
    setStopping(false)
  }
}

## Acceptance Criteria

- [ ] **AC-1:** When a `running` agent node is clicked in `/flow`, the detail panel shows a red "⛔ Stop Agent" button
- [ ] **AC-2:** The stop button does NOT appear for `idle`, `done`, or `error` status agents
- [ ] **AC-3:** Clicking "Stop" shows a browser confirm dialog before proceeding
- [ ] **AC-4:** After confirmation, the button enters a "Stopping..." loading state with spinner
- [ ] **AC-5:** `POST /api/agents/<agentId>/stop` successfully terminates the agent's active session
- [ ] **AC-6:** After successful stop, the agent's status updates to `idle` or `done` via SSE within 5 seconds
- [ ] **AC-7:** If the stop fails, an error message is displayed below the button in red
- [ ] **AC-8:** The endpoint validates `agentId` to prevent path traversal (alphanumeric + hyphen only)
- [ ] **AC-9:** The endpoint returns 404 if the agent has no active session
- [ ] **AC-10:** Multiple rapid clicks on Stop do not cause multiple abort attempts (debounce/disable while in-flight)

## Design Notes

- The stop button should feel "dangerous" — red, with confirmation. This is a destructive action.
- Match existing panel styling in `AgentDetailPanel.tsx` (dark theme, `#161b22` panels)
- Button style: `bg-red-600 hover:bg-red-700 text-white font-semibold py-2 px-4 rounded`
- Consider adding a small cooldown (3s) after stop to prevent re-triggering before SSE updates
- Log all stop actions server-side for audit trail
